# Компактный вывод: что сделано и замеры

Цель — чтобы свёрнутый тул-колл занимал минимум строк, как в Claude Code, а полный вывод открывался явным действием (`Ctrl+O`).

## Текущий вариант: pi 1.0.2 + better-claude-code-ui 0.1.8

С 4 октября 2026 используется локальное расширение
`agent/extensions/zzzz-compact-tools.ts`; `install.sh` копирует его в
`~/.pi/agent/extensions/`. Это авторизованное исключение из прежнего правила
«только готовые расширения»: `/cc-tools detail off` у установленного UI оставляет
до 8 строк превью, а не скрывает вывод.

Поведение:

- одиночный свёрнутый вызов — одна строка с названием и короткими аргументами;
- после видимого промежуточного assistant/thinking-текста перед тулколами
  добавляется пустая строка, если разделителя ещё нет;
- подряд одинаковые инструменты — один заголовок со счётчиком и максимум три
  последние строки (`⎿ →`, затем `→`); при добавлении вызовов двигается только tail;
- stdout, диффы, картинки, результаты MCP и стриминг-превью не рисуются;
- `Ctrl+O` включает прежний подробный рендер; клик по строке тоже раскрывает её;
- группировка строится по реальным соседям в transcript: работает на replay,
  не смешивает разные тулы и разрывается видимым комментарием;
- ошибка даже в скрытой части группы остаётся в счётчике `✗N` заголовка;
- клик раскрывает соседний tool-блок вместе, чтобы не дублировать участников
  смешанной read/search-группы npm-рендерера;
- `/compact-tools on|off|toggle` переключает режим в памяти процесса; новый процесс
  по умолчанию компактный;
- длинные строки обрезаются по ширине терминала, многострочные аргументы соединяются;
- пробел на месте погасшего кружочка не обрезается: текст не скачет горизонтально.

Пример из фактического pty-replay:

```text
 Промежуточный комментарий. После него должна быть пустая строка.

⏺ Read(5 calls · tail 3)
  ⎿ → repos/pi-harness/test-2.md
    → repos/pi-harness/test-3.md
    → repos/pi-harness/test-4.md
```

Расширение патчит только рендер и обработку клика публичных
`ToolExecutionComponent` и `Container` (только обычных контейнеров с прямыми
tool-children), не меняет execution, дерево transcript, результаты или контекст модели.
Группы и mouse-layout — временная проекция рендера, без своих таймеров/кэша сессий. Файлы npm не редактируются; обновления пакетов не стирают файл
расширения. После обновления pi нужно повторить тест: патч использует внутренние поля
компонента, совместимость с будущими версиями автоматически не гарантируется.

Проверка: `node tests/compact-tools.mjs` — одиночные строки, отсутствие stdout,
раскрытие/сворачивание, клик, ошибки, MCP fallback, ширины 1–200 и Unicode,
идемпотентная загрузка, обе фазы мигания, разделитель после комментария,
последние три вызова, границы групп и неизменность дерева transcript.
На установленном пакете проверяются реальные рендереры `bash`, `read`, `write`,
а также реально скрытые native group members и смешанная read/list-группа.

Новый групповой вариант проверен в отдельном Pi 1.0.2 с реальным
better-claude-code-ui 0.1.8, в pty, через `--offline --session <fixture> --tui-mode regular`:
пять Read → один заголовок и три пути, перед заголовком пустая строка,
`OUTPUT_SHOULD_BE_HIDDEN` в ANSI-потоке отсутствует, выход через `/quit` с кодом 0.
Модель и инструменты при replay не запускались. Для прежнего однострочного варианта
пользователь подтвердил отсутствие горизонтального скачка в живом TUI.

## История: прежний pi-claude-code-ui

Ниже — исторические настройки и замеры для прежнего расширения, не руководство
по текущему `better-claude-code-ui`.

## Что было не так

Дефолты `pi-claude-code-ui` оставляли в свёрнутой строке хвост вывода команды (`liveToolPreview`) и до 8 строк превью для `read`/`grep`/`mcp` (`previewLines`), плюс до 8 строк исходника команды (`bashCommandPreviewLines`). Визуально это выглядело так:

```
● Bash ls -la ~/.pi/agent/ ... ; for f in ~/.pi/agent/conf…
└ Done (58 lines) • ctrl+o to toggle
        ]
      }
    }
  }
  Command exited with code 1
```

## Что стало (текущий конфиг)

```json
{ "previewLines": 1, "bashCollapsedLines": 2, "bashCommandPreviewLines": 0,
  "liveToolPreview": false, "diffCollapsedLines": 8 }
```

```
● Bash ls -la ~/.pi/agent/ ... ; for f in ~/.pi/agent/conf…
└ Done (58 lines) • ctrl+o to toggle
```

Плюс `toolBackground: "transparent"` — убирает горизонтальные правила вокруг тул-строк.

## Замеры

Метод: реплей одной и той же реальной сессии (`--tui-mode regular`, без сети и модели, в pty), подсчёт отрисованных строк и строк вывода под строками `Done (N lines)`.

| Конфиг | Всего строк транскрипта | Сумма строк вывода под bash-строками | Медиана на строку |
|---|---|---|---|
| дефолт (8 / 10 / 8 / 5) | 1653 | 366 | 5 |
| промежуточный (3 / 3 / 2 / 2) | 1457 | 194 | 2 |
| финальный (1 / 2 / 0 / off) | **1263 (−24 %)** | **0** | **0** |

Порядок значений: `previewLines` / `bashCollapsedLines` / `bashCommandPreviewLines` / `liveToolPreviewLines`. В финальном варианте `liveToolPreview: false`.

Отдельный A/B по `toolBackground` на том же реплее: количество символов `─` в кадре 2025 → 1865 (уходят правила вокруг тулов), рамки юзер-сообщений и коннекторы остаются — они захардкожены.

## Скрытие thinking

`~/.pi/agent/settings.json`:

```json
{ "defaultThinkingLevel": "max", "hideThinkingBlock": true }
```

и в `~/.pi/settings.json`: `"thinkingMode": "full"`.

Почему оба: `hideThinkingBlock` — настройка pi (блоки не рендерятся), но дефолтный `thinkingMode: "live"` расширения принудительно ставит `hideThinkingBlock = false` на время стрима, показывая содержимое. `"full"` это отключает: во время размышления видна одна строка `Thinking…`, после — `Thought for Ns`.

Проверка на реплее сессии с 5 thinking-блоками: отрисовано ровно 5 строк `Thought for`, утечек текста размышлений — 0 (фрагменты ≥40 символов из каждого блока искались в выводе).

## Что осталось не-Claude-Code

Захардкожено в `pi-claude-code-ui`, настройками не убирается:

1. рамка-бокс вокруг юзер-сообщения (`roundedUserBorder`) — в CC это `> prompt`;
2. группировка вызовов рисуется деревом `├ └ │` вместо буллета `⏺` с отступом `⎿`;
3. форма веток не настраивается — только цвет (`toolBranchColorMode`).

На момент тех замеров штатного способа это убрать не было и собственный код не добавлялся. Текущий вариант выше использует небольшой локальный display-only патч вместо правки 7.5k строк в `node_modules`.
